# Rung-2 Distributional Forest — Real Run (2026-06-17)

> Verdict document for the rung-2 distributional random forest, evaluated head-
> to-head against rung-0 and rung-1 under the frozen deflated-Sharpe gate. All
> numbers are quoted verbatim from `rung2_forest.json` (generated by
> `python tools/path_signal.py rung2 --n-folds 5 --horizons 6 12` on the cached
> 3-year BTC 4h series). Pre-registration: `PREREGISTRATION.md`; design:
> `docs/research-log/specs/2026-06-17-pathsig-rung2-distributional-forest-design.md`.

## TL;DR — kill rule FIRES on both horizons

Rung-2 does **not** clear the gate on either horizon. h=6 is catastrophically
negative; h=12 is positive and nominally beats both lower rungs on total_R, but
is **not deflation-significant** (DSR = 0.000) and breaches the −15R drawdown cap
by >4×. Per the pre-registered kill rule ("rung 2 fails to beat rung 1 **OR**
fails the gate ⇒ the 'framework was the limiting factor' thesis is falsified on
existing data"), the thesis is **FALSIFIED on existing data**. The lockbox
remains **sealed** (no horizon cleared the gate). No parameter rescue.

| | |

| Deflation budget | `n_trials = 8 × 3 × 2 = 48` |
| Gate | deflated Sharpe ≥ 0.95 (both horizons judged under the full 48-trial budget) |

## Per-horizon results (quoted from `rung2_forest.json`)

### h = 6 — FAIL (does not beat rung-1; fails gate)

- trades = **584** / 2797 events
- **fixed-cap frame:** total_r = **−220.93**, max_drawdown_r = **−229.16**, within_cap = **False** (cap is −15R)
- **risk-adjusted frame:** Sharpe = **−0.190**, DSR = **0.000**, MAR = **−0.868**, net_return = **−0.464**
- head-to-head: beats_rung0 = **False** (−220.93 vs floor +9.31), beats_rung1 = **False** (−220.93 vs −22.33)
- verdict: `clears_gate = False` — *"forest does not beat the rungs below it"*

The forest actively destroys value at h=6 — far worse than even the negative
control (rung-1 −22.33R). The selected configs varied per fold (structures
[3,30,4], [3,60,4], [5,30,8], [3,60,8], [5,30,4]); inner-CV selection did not
rescue OOS.

### h = 12 — FAIL (beats both rungs on total_R, but not deflation-significant; breaches cap)

- trades = **198** / 2793 events
- **fixed-cap frame:** total_r = **+35.93**, max_drawdown_r = **−63.60**, within_cap = **False** (cap is −15R)
- **risk-adjusted frame:** Sharpe = **+0.033**, DSR = **0.000**, MAR = **+0.261**, net_return = **+0.080**
- head-to-head: beats_rung0 = **True** (+35.93 vs floor +24.03), beats_rung1 = **True** (+35.93 vs −25.72)
- verdict: `clears_gate = False` — *"path model helps but is not deflation-significant"*

The positive total_R is **not a real edge**: (a) DSR = 0.000 — under the
pre-registered 48-trial deflation, an OOS Sharpe of 0.033 is crushingly
insignificant; (b) the −63.6R drawdown is >4× the −15R cap, i.e. the same
structural drawdown wall that has killed every family in this program. The
learned conditional path distribution did not harvest drift the handcrafted
signals missed; it re-encountered the same wall.

## Verdict (the boolean that drives the kill rule)

```
success = (beats_rung0 AND beats_rung1 AND clears_gate)
```

- h=6:  False — does not beat rung-1, does not clear gate.
- h=12: False — clears_gate is False (DSR = 0.000).

**Neither horizon succeeds.** The kill rule fires.

## Kill-rule outcome (pre-registration, no parameter rescue)

> *"rung 2 fails to beat rung 1 OR fails the gate ⇒ the 'framework was the
> limiting factor' thesis is falsified on existing data; escalate to a separate
> new-data program."*

Both conditions are met (h=6 fails to beat rung-1; h=12 fails the gate). The
hypothesis that a **learned** conditional path distribution would find edge the
**handcrafted** rung-0/rung-1 signals could not harvest is **falsified on the
existing data**: a flexible non-parametric model, given the same frozen feature
set and decision policy, lands on the same structural drawdown wall with no
deflation-significant OOS Sharpe. The framework was not the limiting factor.

**Standing recommendation:** a separate new-data program (the path signal is
exhausted on existing free data, consistent with the closed families in the
prior program). Not a regime filter, not a tuning pass.

## Lockbox status — SEALED

The one-touch lockbox tail is **not opened**. Per pre-registration it is opened
only after a horizon clears the gate OOS; no horizon did (`clears_gate = False`
on both h=6 and h=12). The `open_lockbox()` function exists in
`rung2.py` but was never invoked. The sealed tail remains untouched.

> Methodology note for the record: `open_lockbox` trains on all usable data and
> scores the final-20% tail with no embargo at the train/tail boundary (consistent
> with how rungs 0/1 seal the lockbox by exclusion). This is moot here since the
> lockbox was never opened; noted only so the design is fully on record.
